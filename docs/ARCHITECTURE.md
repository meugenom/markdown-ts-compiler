## 1. System Overview (The Pipeline)

The compiler operates on a **Two-Pass Strategy** to ensure that complex nested structures.

- **Input:** Raw Markdown string.
- **Pass 1 (Block Parsing):** The `Tokenizer` identifies high-level structural blocks (Headings, Code Blocks, Tables, Captions) and removes them from the text stream.
- **Pass 2 (Inline Parsing):** The engine recursively processes the remaining text content within those blocks to find inline elements (Bold, Links, Inline Code).
- **Pass 3 (Rendering):** The `Render` engine walks the resulting Abstract Syntax Tree (AST) and generates HTML using specialized HTML block classes.
- **Output:** A clean, semantic HTML string.

---

## 2. The Tokenizer (Parsing Phase)

**File:** `src/Tokenizer.ts`

The `Tokenizer` class is the core parser. It maintains the state of the raw text (`this.text`) and builds the AST (`this.ast`).

### Key Methods

1. `putRootChildren()`:
    - Iterates through the raw text looking for **Block-Level** patterns defined in `Grammar.ts`.
    - When a block is found (e.g., a Code Block), it extracts the token, creates an `ASTNode`, and **slices** the matched text out of `this.text`.
    - This prevents the inline parser from accidentally matching content inside a code block (e.g., matching `$` inside a code block as a formula).

2. `putInlineChildren(node: ASTNode)`:
    - Recursively processes the `raw` property of terminal nodes (like Paragraphs, Headings, List Items).
    - Looks for **Inline-Level** patterns (Bold, Links, Badges, Inline Code).
    - **Constraint:** It does not decompose matched inline tokens further. Once a bold word is found, its content is stored as-is to maintain performance.

### Supported Block Types

- `CAPTION`: Frontmatter metadata.
- `HEADING`: H1-H5.
- `CODE_BLOCK`: Fenced code blocks with language detection.
- `TABLE`: Markdown tables with headers and body.
- `LIST`: Unordered lists, including task lists (`[ ]`, `[x]`).
- `QUOTE`: Blockquotes.
- `FORMULA_BLOCK`: Display math (`$$`).

## 4. The Renderer (Generation Phase)

**File:** `src/Render.ts`

The `Render` class takes the AST generated by the Tokenizer and converts it into HTML.

### Key Logic

- `html()`: The entry point. It calls `renderNodes()` on the root children.
- `renderNodes(nodes: ASTNode[])`:
    - Iterates through the AST nodes;
    - Uses a `switch` statement on `node.type` (from `TokenType` enum);
    - Instantiates the appropriate HTML block class (e.g., `new CodeBlockHTML(token)`);
    - Handles **Asynchronous** rendering for blocks that require external engines (Shiki for code, KaTeX for math).

## 5. HTML Block Implementations

**Directory:** `src/htmlblocks/`.

Each complex element has a dedicated class responsible for generating its specific HTML structure and handling external dependencies.

### Key Classes:

`CodeBlockHTML.ts`:
    - Async: Initializes 'Shiki' highlighter on first render.
    - Features: Generates line numbers, a "Copy" button with Code logic.
    - Fallback: If 'Shiki' fails, it falls back to escaping raw text.

`FormulaHTML.ts`:
    - Async: Uses KaTeX to render LaTeX strings.
    - Features: Generates a container with a "Formula" header.
    - Fallback: Catches KaTeX errors and displays the raw formula text safely.

`CaptionHTML.ts`:
    - Validation: Uses `ValidateCaption.ts` to check metadata integrity before rendering.
    - Features: Generates a structured layout with thumbnail, title, date, tags, and navigation links.

`HeaderHTML.ts`:
    - Generates `<h1>` to `<h6>` tags.
    - Automatically generates `id` attributes for anchor links (slugified from the heading text).

`BadgeHTML.ts` & `ColorTextHTML.ts`:
    - Handles the specific `[[]]` syntax for badges and colored text, mapping them to Tailwind utility classes (e.g., `md-badge-blue`).

## 6. Data Structures (AST & Tokens)

**File:** `src/Token.ts` & `src/Types.ts`

### Token Interfaces

The `Token.ts` file defines TypeScript interfaces for every possible token type. This ensures type safety throughout the pipeline.

`captionToken`: Includes fields like `date`, `slug`, `tags`.
`codeBlockToken`: Includes `language` and `code`.
`headToken`: Includes `type` (H1-H5) and `value`.

### TokenType Enum

**File:** `src/Types.ts`

A comprehensive enum (`TokenType`) that maps string identifiers (e.g., `"HeadingFirst"`) to their semantic meaning. The Renderer uses this enum to determine which HTML block class to instantiate.

## 7. Error Handling & Fallbacks

The compiler is designed to be robust against malformed Markdown.

1. Caption Validation:
    - If a caption block is malformed (e.g., missing date, invalid slug), the `ValidateCaption` class replaces the invalid field value with an error message string (e.g., `"Missing date"`).
    - The renderer then displays these error messages within the UI instead of crashing.

2. Unmarkable Blocks:
    - If a block is explicitly marked as unmarkable (using `\\* ... \\*`), the content is preserved as raw text without parsing, preventing accidental formatting.

3. External Engine Failures:
    - If Shiki (syntax highlighting) or KaTeX (math) fail to initialize or throw errors, the Renderer catches the exception.
    - It falls back to rendering the raw code/math string with HTML entities escaped (e.g., `<` becomes `&lt;`) to prevent XSS and layout breakage.

---

## 8. External Dependencies

The compiler integrates with two major libraries for advanced features:

1.  **Shiki (`@shikijs/core`)**:
    *   Used for syntax highlighting in Code Blocks.
    *   Supports Light/Dark mode themes (`github-light`, `github-dark`).
    *   Loaded asynchronously to keep initial bundle size small.

2.  **KaTeX**:
    *   Used for rendering mathematical formulas.
    *   Supports both inline (`$...$`) and block (`$$...$$`) modes.
